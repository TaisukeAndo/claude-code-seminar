## 4. プロンプトエンジニアリングとは

### このセクションで学ぶこと
- みなさんが普段やっていることに「名前をつける」
- プロンプトエンジニアリングの限界（なぜ次の概念が必要になるのか）

### 今日の起点：みなさんは既にやっている

「AIをどう使うか」を日々工夫しているみなさんは、実はすでに**プロンプトエンジニアリング**をやっています。まずここに名前をつけることから始めます。

**プロンプトエンジニアリングとは：「AIへの1回の指示（プロンプト）を、うまく書く技術」**

たとえば、こういう工夫はすべてプロンプトエンジニアリングです。

| 普段やっている工夫 | 例 |
|--------------------|-----|
| 役割を与える | 「あなたはプロの編集者です」 |
| 出力の形を指定する | 「表で答えて」「箇条書き3点で」 |
| 例を示す | 「こういう感じで書いて（例）…」 |
| 条件を絞る | 「初心者向けに」「200字以内で」 |

### 限界が見えてきた

プロンプトエンジニアリングは強力です。でも、使い込むにつれて**2つの限界**に気づくはずです。

| 限界 | 具体的に何が起きるか |
|------|----------------------|
| **1回限り** | 同じ指示を毎回書き直す必要がある。セッションをまたいで記憶してくれない |
| **1対1** | 人間が1つのAIに指示を出すだけ。「AIが自律的に複数のことを処理する」にはならない |

この限界を越えるのが、今日の後半で出てくる**コンテキストエンジニアリング**です。

でもその前に、「どのAIを使うか」という話をしておく必要があります。
