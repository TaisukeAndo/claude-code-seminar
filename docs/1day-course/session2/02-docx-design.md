## 2.5. Session 1 とのつながり

Session 1 で学んだとおり、AI（大規模言語モデル）は「与えられた文脈をもとにテキストを生成する」仕組みで動いています。

ドキュメント生成においてよくある失敗の根本原因は、**AI に渡す文脈（コンテキスト）が不足していること**です。

**指示の比較**

```
情報が少ない指示:
「企画書を作って」

→ AI は目的・対象・ページ数・会社の特徴を何も知らない状態で書き始めます。
  出力がばらつく原因はここにあります。
```

```
情報が十分ある指示:
「〇〇社向けの新サービス提案の企画書を作ってください。
 A4 で 4 ページ、構成は「課題提起・解決策・費用対効果・スケジュール」です。
 弊社の強みとして、△△の導入実績（〇社以上）も入れてください。」

→ AI に必要な情報が揃っているため、出力の精度が上がります。
```

**スキル（/コマンド）は、この「文脈の渡し方」を定型化した仕組みです。**  
スキルを使うと、毎回同じ品質の情報を AI に渡すことができます。

## 2.6. 代表的なドキュメントの種類

このセッションでは、以下の 3 種類を対象とします。

| ドキュメント | 目的 | 特徴 |
|---|---|---|
| **企画書** | 新しい取り組みや事業を提案する | 説得力のある構成・根拠となるデータが重要 |
| **報告書** | 業務・プロジェクトの状況を共有する | 事実の正確な記録・簡潔な記述が重要 |
| **議事録** | 会議の内容・決定事項を記録する | 発言者・決定事項・次のアクションの明記が重要 |

このセッションでは、最も作成手順が複雑な**企画書**を主な例として扱います。  
他のドキュメントについても、基本的な操作の流れは同じです。

---

## 2.7. 企画書作成の現行フロー

現在、多くの方が企画書を作成する際に以下のような流れで作業しています。

```
STEP 1: クライアントの要望や背景を確認する
           （ヒアリング・過去のやりとりを確認）
         ↓
STEP 2: 必要な情報・アイデアを整理する
           （調査・箇条書きでまとめる）
         ↓
STEP 3: ドキュメント形式にまとめる
           （Word や Google ドキュメントで清書する）
         ↓
STEP 4: 誤りや体裁を確認する
           （誤字確認・フォーマット統一・レビュー依頼）
```

STEP 2〜3 の「整理してまとめる」部分が最も時間のかかる工程です。  
ここを Claude Code のスキルに任せることで、作業時間を短縮できます。

---

## 2.8. AI に置き換えるとどうなるか

上記のフローを Claude Code のスキルに置き換えると、以下のようになります。

```
STEP 1: コンテキスト収集（サブエージェントが担当）
           クライアント情報・要望・参考資料を自動収集
         ↓
STEP 2: 情報の統合（スキルが処理）
           収集した情報を構造化・整理
         ↓
STEP 3: ドキュメント生成（スキルが出力）
           Word 形式（.docx）で企画書を自動生成
         ↓
STEP 4: レビューと修正（あなたが確認・AI が修正）
           内容を確認して、修正が必要な箇所を指示する
```

### サブエージェントとは

::: info サブエージェントについて
「サブエージェント」とは、メインの処理とは別に特定の作業を担当する補助的な AI の処理のことです。

情報収集をメインの処理と同じ会話の中で行うと、会話の「メモリ（文脈）」が情報で埋まってしまい、出力の品質が下がることがあります。これを「コンテキスト汚染」と呼びます。

情報収集を専用のサブエージェントに分離することで、メインのスキルが精度の高い出力を維持できるようになります。
:::
