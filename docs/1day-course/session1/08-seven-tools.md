## 8. コンテキストエンジニアリングの要素 ― 7つの道具と解決する問題

### このセクションで学ぶこと
- 7つの道具それぞれが「どの問題を解決するか」
- 2つのグループ： 安全・制御グループ ／ 🛠 効率・準備グループ

### 7つの道具は「問題の解決策」として生まれた

コンテキストエンジニアリングを実現する道具は7つあります。それぞれを「なんとなく覚える」のではなく、**「どんな問題があってこれが生まれたか」** で整理します。

| グループ | 道具 | 解決する問題 |
|----------|------|-------------|
|  安全・制御 | パーミッション | 意図しない操作を防ぎたい |
|  安全・制御 | フック | AIの「お願い」では守られない安全処理を確実に実行したい |
|  効率・準備 | サブエージェント | 大きなタスクで机（コンテキスト）が圧迫される |
|  効率・準備 | MCPサーバー | 外部サービスへの接続を毎回個別に作るのが大変 |
|  効率・準備 | ルールズ | CLAUDE.md が長くなりすぎて管理できない |
|  効率・準備 | スキルズ | 繰り返す手順をその都度コンテキストに置きたくない |

以下、ひとつずつ見ていきます。

---

###  安全・制御グループ

#### ① パーミッション（Permissions）― 意図しない操作を防ぐ

**問題：** Claude Code は自律的に動く。ということは、**人間が目を離した間に、やってほしくないことをやってしまう**可能性がある。

- 重要なファイルを誤って削除する
- 意図しないAPIを叩いてコストが発生する
- プロンプトインジェクション攻撃を受けたとき、悪意ある指示を実行してしまう

**解決策：パーミッション**

> **【用語】パーミッション（Permissions）**
> Claude Code が「何をしてよいか／してはいけないか」を制御する仕組み。ファイル編集・コマンド実行・外部ツール呼び出しなどに対し、**許可・拒否・確認**を設定できる。`.claude/settings.json` に記述。
> **使い方の例：** `git status` など信頼できるコマンドは許可リストに入れて毎回の確認をスキップ。危険なコマンドは拒否リストでブロック。
> **利点：** 自律的に動かしつつ、意図しない操作を未然に防げる。安全性と利便性のバランスを自分で調整できる。
> （ソースあり：Claude Code 公式ドキュメント）

「自律的に動かせる」と「意図しないことをやられたくない」は矛盾します。パーミッションはその矛盾を解消する仕組みです。プロンプトインジェクション対策としても効果があります（悪意ある指示が来ても、許可されていない操作は実行できない）。

---

#### ② フック（Hooks）― 「AIのお願い」ではなく「確実な自動実行」

**問題：** CLAUDE.md にルールを書いても、AIは「守る可能性が高い」だけで**100%ではありません**。「必ず実行してほしい処理」（ログ記録・自動整形・危険なコマンドのブロックなど）を、AIの判断に委ねたくない。

**解決策：フック**

> **【用語】フック（Hooks）**
> Claude Code の動作の特定タイミング（プロンプト送信前・ツール実行の前後・セッション開始時など）で **自動実行**されるシェルコマンドやスクリプト。
> **最大の特徴：** AIの判断を経由せず **「100%確実に発火する」**（決定論的）。LLMがどう判断しようと、条件に合えば必ず実行される。
> **実用例：** ファイル編集後の自動整形、危険なコマンドの自動ブロック、ログ記録、通知。
> **設定方法：** `.claude/settings.json` に「イベント名 → 条件 → 実行内容」の形で記述。
> （ソースあり：kkclaw's blog／StartLink）

| | CLAUDE.md のルール | フック |
|---|---|---|
| 実行 | AIが**守ろうとする**（確率的） | 条件に合えば**必ず実行**（決定論的） |
| 性質 | 「お願い」 | 「自動の仕掛け」 |

### 🛠 効率・準備グループ

#### ③ サブエージェント ― 机を分割してコンテキストを守る

**問題：** 大きなタスク（「このプロジェクト全体を調査して修正案を出して」など）を1つの Claude Code でやると、**膨大なファイルや中間結果がコンテキストウィンドウを埋め尽くす**。机が溢れて、後半では精度が落ちる。

**解決策：サブエージェント**

> **【用語】サブエージェント（SubAgent）**
> メインの Claude Code から**呼び出される**、特定タスク専用の独立したAIアシスタント。**独自のコンテキストウィンドウ（机）を持ち**、メインとは切り離されて動作する。
> **使い方の例：** 「フロントエンド担当」「バックエンド担当」といった専門サブエージェントを複数同時に動かし、結果をメインに集約する。
> **利点：** 複数が並列で作業でき、大規模タスクを効率よく分割できる。さらに、サブエージェントの作業はメインのコンテキストを圧迫しない。
> （ソースあり：サーバーワークスエンジニアブログ／SHIFT AI TIMES）

```
   エージェント（メイン＝司令塔）
        │  仕事を切り分けて配る
        ├──→ サブエージェントA（自分の机で作業）
        ├──→ サブエージェントB（自分の机で作業）
        └──→ サブエージェントC（自分の机で作業）
        ↑  各自が結果の要約だけを返す
```

#### ④ MCPサーバー ― 外部接続を「毎回作らなくていい」に

**問題：** Claude Code を Googleドライブ・Slack・GitHub などにつなごうとすると、これまではサービスごとに**個別の連携実装が必要**だった。標準化されていないので、毎回ゼロから作る。

**解決策：MCPサーバー**

「コンセントの形を統一する」ように標準化されたのが MCP（Model Context Protocol）です。MCPサーバーという接続口さえ用意すれば、さまざまな外部サービスに Claude Code からつなげます。

**ただし注意：** 外部につながることは新たなリスクでもあります。だからこそ、パーミッションで「MCPサーバー経由での操作をどこまで許可するか」を設定することが重要です。

---

#### ⑤ ルールズ（Rules）― CLAUDE.md の肥大化を防ぐ

**問題：** CLAUDE.md に何でも書いていると、**どんどん長くなる**。長くなると①コンテキストを大量に消費する、②AIの遵守率が下がる、③チームで管理しにくくなる。

**解決策：ルールズ**

> **【用語】ルールズ（Rules）**
> CLAUDE.md に書く常時指示を、**トピックごとに分割・整理**できる仕組み（`.claude/rules/` 内の Markdown ファイル）。
> **使い方の例：** `code-style.md` にコーディング規則、`testing.md` にテスト方針を分けて書く。ファイルパスのパターンで「このフォルダを操作するときだけ読む」という条件付きもできる。
> **利点：** CLAUDE.md の肥大化を防ぎ、チームのルールをバージョン管理で共有できる。
> （ソースあり：アイドリ／SIOS Tech Lab）

| | CLAUDE.md | ルールズ |
|---|---|---|
| 管理 | 1枚に全部 | テーマ別に分割 |
| 読み込み | 常に全部読む | 条件に合ったものだけ読む |

---

#### ⑥ スキルズ（Skills）― 手順書を「必要なときだけ出す」

**問題：** 繰り返す手順（コミット手順・PRのまとめ方など）をCLAUDE.mdに書いておくと、使わないときも**常にコンテキストを占有する**。机が常に散らかっている状態。

**解決策：スキルズ**

> **【用語】スキルズ（Skills）**
> Claude Code に「**再利用可能な手順・知識・ワークフロー**」を追加する仕組み。`/スキル名` で呼び出すか、Claude が自動で判断して使う。
> **実用例：** `/commit`（コミット手順）、`/pr-summary`（PRのまとめ）など、繰り返す手順を登録しておく。
> （ソースあり：Claude Code 公式ドキュメント／SIOS Tech Lab）

| | CLAUDE.md | スキルズ |
|---|---|---|
| 読み込みタイミング | 毎回のセッションで**常に**読まれる | **呼び出されたときだけ**読まれる（オンデマンド） |
| コンテキストへの影響 | 常に机を占有する | 使うときだけ机に出す |

「いつも必要なこと」は CLAUDE.md、「ときどき必要な手順」はスキルズ、という使い分けが**コンテキストエンジニアリングの実践**そのものです。

---

### 7つの道具 + 2つの問題の整理

| 道具 | 解決する問題 | 効果 |
|------|------------|------|
| パーミッション | 意図しない操作・プロンプトインジェクション | 許可範囲を制御して安全に動かす |
| フック | AIの不確実な遵守 | 必ず実行される自動処理を設定する |
| サブエージェント | コンテキストの圧迫 | 独立した机で分担し、メインを守る |
| MCPサーバー | 外部接続の個別実装コスト | 標準規格で一元化する |
| ルールズ | CLAUDE.md の肥大化 | テーマ別に分割・条件付き読み込み |
| スキルズ | 常時コンテキストの無駄な占有 | 必要なときだけ読み込む |
| CLAUDE.md | 毎回同じ指示を書く手間・記憶の消去 | 永続的な指示書として自動読み込み |

### （名前だけ紹介）押さえておくと安心な2つの言葉

> **ハーネスエンジニアリング**
> Claude Code 公式ドキュメントでは Claude Code 自体を「agenticハーネス」と呼んでいます。「ハーネスエンジニアリング」という固有の定義はまだ確立されていないため、**今日は名前の紹介だけ**にとどめます。
> （ソースあり：Claude Code 公式ドキュメント）

> **サンドボックス（Sandbox）**
> Claude Code の操作を隔離された安全な環境に閉じ込める仕組み。パーミッションと組み合わせることで、「安全な範囲の中で自由に動かす」が実現します。主にエンジニア向けのセキュリティ機能なので、**名前だけ**覚えておけば十分です。
