## 6. Claude Codeってなんだ ― 能力とリスク

### このセクションで学ぶこと
- Claude Code とは何か（チャットAIとの決定的な違い）
- Claude Code がどう動いているか（agenticループ）
- MCP という「外部サービスへの接続規格」
- **能力が増えた分だけリスクも生まれる**（プロンプトインジェクション攻撃）

### 課題：チャットAIでは「実際に作業してもらう」ことができない

プロンプトエンジニアリングをどれだけ磨いても、チャット形式のAIには**根本的な限界**があります。

| 限界 | 具体的に何が起きるか |
|------|----------------------|
| 返事するだけ | 「このファイルを直して」と言っても、直し方を教えてくれるだけ。実際には人間が手を動かす必要がある |
| 1回で終わり | 複数ステップにまたがる作業（読む→判断→修正→確認）を連続して自律実行できない |
| 外とつながれない | パソコンのファイルや外部サービスに直接アクセスできない |

### 解決策：Claude Code

> **【用語】Claude Code（クロードコード）**
> Claude（LLM）をターミナル（コマンドライン）から操作できるようにしたツール。ファイルの読み書き・編集・検索・コマンド実行・Git操作を自律的に行える「エージェント型アシスタント」。2025年2月に Anthropic がリリース。
> （ソースあり：AI経営総合研究所／Claude Code 公式ドキュメント）

| | 普通のClaude（Web版・チャット） | Claude Code |
|---|---|---|
| できること | テキストで **返事をする** だけ | **ファイルを読み書き**し、コマンドも実行する |
| 動き方 | 1回聞く → 1回答える | 目標を渡す → 自律的に何ステップも動く |
| たとえると | 相談に乗ってくれる相手 | 実際に手を動かして作業する相棒 |

> **Claude Code の最大の特徴は「ファイルの処理」です。**

### Claude Code はどう動いているのか（agenticループ）

Claude Code は、次の3ステップを**自律的に繰り返す**ことで複雑な作業を進めます。

```
① コンテキスト収集（必要なファイルや情報を読む）
        ↓
② アクション実行（編集する・コマンドを動かす）
        ↓
③ 結果検証（うまくいったか確認する）
        ↓
   （必要ならまた①に戻る）
```

この自律的な繰り返しを **「agenticループ」** と呼びます。

> **【用語】エージェント（Agent）**
> 人間が一つひとつ指示を出さなくても、**目標を与えるだけで自律的に判断・行動・検証を繰り返す**AIの動作様式。**Claude Code 自体がエージェントです。**

| | プロンプトエンジニアリング | エージェント（Claude Code）|
|---|---|---|
| やりとり | 人間が指示 → AIが **1回** 返事 | 人間が **目標** を渡す → AIが **自律的に複数ステップ** 実行 |
| 人間の介入 | 毎回必要 | 途中は不要（自律実行） |

### MCP ― 外部サービスにもつながる

Claude Code は自分のパソコンの中だけでなく、**Googleドライブや Slack などの外部サービス**にもつなげます。

> **【用語】MCP（正式名称：Model Context Protocol／モデル・コンテキスト・プロトコル）**
> AIと外部ツール・サービスをつなぐための **「共通の接続規格（プロトコル）」**。Anthropic が2024年11月にオープンソースとして公開。現在は OpenAI・Google・Microsoft などにも採用されつつある業界標準。
> （ソースあり：Digeon／CYLLENGEブログ）

> **【用語】MCPサーバー**
> MCPに対応した「外部サービスへの接続口」。Googleドライブ・Slack・GitHub などに、Claude Code からアクセスできるようにする橋渡し役。
> **実例：** GoogleドライブのMCPサーバーを設定すると、「ドライブのXXXというファイルを読んで要約して」と Claude Code に指示できる。
> （ソースあり：Uravation）

---

### ここで立ち止まる：「能力が増えた」ことのリスク

ここまでで Claude Code は強力だとわかりました。しかし、**能力が増えた分だけリスクも増えます。**

> チャットAIが「返事するだけ」だった頃は、間違えても画面の中の話でした。
> Claude Code が「ファイルを操作し、外部サービスにもつながる」ようになると、
> 間違いの影響は**実際のデータ・システム全体**に及びます。

**リスク① 意図しない操作**
Claude Code は自律的に動きます。目標の解釈がずれると、重要ファイルの削除・意図しないコマンドの実行・想定外のAPI呼び出しが起きる可能性があります。

**リスク② プロンプトインジェクション攻撃**

> **【用語】プロンプトインジェクション攻撃（Prompt Injection Attack）**
> 悪意ある指示文を入力や外部データに紛れ込ませ、AIを本来の動作から逸脱させたり情報を漏らさせたりする攻撃手法。
> **Claude Code 特有の危険性：** Claude Code はファイルやウェブを自律的に読み込む（agenticループ）。そのため、外部から読み込んだデータの中に悪意ある指示が仕込まれていても、AIがそれを「正当な指示」と解釈して実行してしまう可能性がある（間接型プロンプトインジェクション）。
> （ソースあり：トレンドマイクロ）

チャットAIなら「自分が書いたプロンプト」だけがAIへの指示でした。Claude Code は**外部ファイルやウェブページの内容もAIへの入力になる**ため、「外から指示を混入させる」攻撃が成立します。

### まとめ
- Claude Code は「ファイル操作・コマンド実行ができる自律型エージェント」
- MCP で外部サービスにもつながる → できることがさらに増えた
- **でも能力が増えた分、リスクも増えた**（意図しない操作・プロンプトインジェクション）
- 次：このリスクを抑えながら Claude Code を使いこなすための「設計技術」= コンテキストエンジニアリング
