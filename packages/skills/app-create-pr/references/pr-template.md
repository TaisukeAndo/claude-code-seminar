# PRのタイトルと説明の書き方

読む人は、プログラミングに詳しくない人でもある。画面でどう変わるかを中心に書き、
専門用語は初出で一言説明する。コードの細かい説明は書かない。

## タイトル

「何を、どうしたか」を1行で書く。

- 良い例: ボタンを大きくして、スマートフォンで押しやすくする
- 悪い例: CSS修正、update

## 説明

```markdown
## 何を変えたか
- （画面でどう変わるかを、箇条書きで。2〜4項目）

## なぜ変えたか
- （依頼の内容、解決したいこと）

## どう確認したか
| 項目 | 結果 |
|---|---|
| （確認した項目） | OK |

## 確認してほしい点（プレビュー環境）
- パソコンとスマートフォンの両方で、確認用のURLを開く
- （変更した画面で、押してほしいボタン・見てほしい場所）

## 注意
- （データの表を変えた、設定を足した、など。なければ「なし」）
```

## 書くときの決まり

- 確認用のURLは、PRのコメントに自動で出る。説明に書き込むときは、コメントに出た実際のURLだけを使う
- 個人情報・トークン・`.env` の値は書かない
- 確認していない項目を、OKと書かない。確認できなかった項目は「未確認」と書く
- 「マージは利用者が確認してから行う」ことを、PRに書く必要はない（利用者への報告で伝える）
