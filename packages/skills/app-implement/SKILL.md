# app-implement スキル（実装Skill）

変更の依頼を受けて、PRを作るところまでを、決まった順番で進める。

> 実装Skillを呼ぶ → ブランチを作る → 実装 → テスト → 改善 → PRを作成

このスキルは、同じ `.claude/skills/` に入れた `app-test`（テストSkill）と
`app-create-pr`（PR作成Skill）を呼び出す。3つをそろえて入れて使う。

## 守ること

1. **最初に `.claude/rules/expression-rules.md` を読み、その表現のルールに従う。**
   ファイルがなければ、このスキルの [assets/rules/expression-rules.md](assets/rules/expression-rules.md) を
   `.claude/rules/expression-rules.md` にコピーする（コピーすることを利用者に一言伝える）
2. **mainブランチには直接変更しない。** 変更は必ず作業用ブランチで行う
3. **依頼の範囲だけを変える。** ついでの整理や、頼まれていない機能を足さない。範囲を超える必要が出たら確認する
4. **作業の前に、何をするかを短く説明する。** PRを作る前に、確認した内容を利用者に報告する
5. **公開してよい情報だけを扱う。** 個人情報・トークン・`.env` の値を、コード・コミット・PR・会話に入れない
6. **データの表（マイグレーション）は、既存のファイルを書き換えず、新しいファイルを足す。**
   データを消す変更は、実行前に説明して承認を得る
7. **マージはしない。** 本番に反映する最後の判断は、利用者が行う

## 手順

### 0. アプリの状態を調べる

1. `git status` と `git branch --show-current` を見る。未コミットの変更があれば、触らずに利用者へ伝えて扱いを確認する
2. `git switch main` → `git pull` で、mainを最新にする
3. `README.md`、`CLAUDE.md`、`requirements.md`、`package.json` の `scripts` を読み、
   このアプリの起動方法とコマンドを把握する（詳細は [references/stack-detection.md](references/stack-detection.md)）

### 1. 依頼を確認して、ブランチを作る

1. 依頼を1〜3文で言い直して確認する。曖昧なら**1問ずつ**質問する
2. 大きすぎる依頼（複数の機能にまたがる等）は、PRを分けることを提案する。**1つのPRに、1つの目的**
3. mainから作業用ブランチを作る。名前は `feature/<内容>`・`fix/<内容>`・`improve/<内容>` のどれかで、
   内容は英数字とハイフンの短い名前にする（例: `improve/bigger-button`）

### 2. 実装

1. 変更前に、関係するファイルを読み、既存の書き方に合わせる
2. 依頼の範囲だけを変える
3. 小さな単位でコミットする。メッセージは「何を変えたか」を1行で書く

### 3. テスト（app-testスキルを使う）

app-testスキルで、変更した機能とその周りを確認する。
**問題があれば原因を調べて直し、もう一度テストする。** 問題がなくなるまで繰り返す。
直らないときは、PRを作らず、状況と原因の候補を利用者に伝えて相談する。

### 4. 確認内容を報告する

PRを作る前に、利用者へ次を報告する。

- 何を変えたか（画面でどう変わるか）
- テストの結果一覧
- 気になる点（あれば）

### 5. PRを作る（app-create-prスキルを使う）

app-create-prスキルで、PRを作る。PRのURLと、確認用のURL（あれば）を利用者に渡す。
**【あなたにお願いします】** PRの画面とプレビュー環境で確認し、問題なければ利用者がマージすること。

## 修正の依頼が続いたとき

PRを出したあとに「ここも直して」と言われたら、**同じブランチ**で手順2〜5を繰り返す。
PRは作り直さず、pushすれば更新される。
