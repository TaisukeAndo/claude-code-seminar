# 報告書のひな形

`.security-reports/YYYYMMDD-security-check.md` に、次の形で書く。秘密の値は書かない。

```markdown
# セキュリティ点検の報告（YYYY年MM月DD日）

対象: <アプリ名>（<リポジトリ名>、<点検したブランチ>）
点検の範囲: アプリのリポジトリ（パソコン本体は対象外）

## 1. まとめ

| 重大 | 要対応 | 任意 | 未確認 |
|---|---|---|---|
| 1 | 2 | 3 | 1 |

最初に直すもの: <重大の項目名を1つ>

## 2. アプリの構成

- 画面: public/
- API: src/index.js
- データベース: D1（表: items）
- ログイン: なし

| 方法 | URL | ログインが必要か | 扱うデータ |
|---|---|---|---|
| GET | /api/items | 不要 | 全員分の一覧 |

## 3. 見つかったこと

### 3.1. 【重大】<項目名>（観点 C1）

- 何が起きうるか: <利用者の目線で1〜2文。例: URLを知っている人なら誰でも、登録されたデータを消せる>
- 場所: src/index.js 52行目
- 直し方: <1〜3文>
- 直したあとの確かめ方: <1文>

### 3.2. 【要対応】...

## 4. 問題がなかった観点

- A1〜A5（秘密情報）: 問題なし
- ...

## 5. 未確認の項目

- <項目>: <確かめられなかった理由と、確かめるために必要なこと>
```

## 書き方の決まり

- 「何が起きうるか」は、技術の言葉ではなく、利用者に起きることで書く
- 攻撃の具体的な手順や、攻撃に使う入力の例は書かない
- 見つからなかった項目も「問題なし」として残す（点検したことが分かるようにする）
