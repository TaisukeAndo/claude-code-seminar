# テスト確認項目

工程3で使う。`requirements.md` の「確認の観点」を先頭に足して、実際に操作して確認する。
結果は「項目／結果（OK・NG）／気づいたこと」の一覧で報告する。

## 起動

- [ ] `npm run db:local` がエラーなく終わる（ローカルのD1に表ができる）
- [ ] `npm run dev` で起動し、localhostのアドレスが表示される
- [ ] そのアドレスをブラウザで開くと、画面が表示される

## 画面と操作

- [ ] 要件の「最初に作る機能」が、書いたとおりの操作で動く
- [ ] 入力が空のまま送ったときに、分かりやすい表示になる（エラーで止まらない）
- [ ] ページを再読み込みしても、登録したデータが残っている
- [ ] 文字が小さすぎず、ボタンが押しやすい大きさになっている
- [ ] ブラウザの幅を狭くしても（スマートフォンの幅）、表示が崩れない

## API（`curl` でも確認する）

- [ ] `GET /api/health` が成功（200）を返す
- [ ] データの取得・登録・削除のAPIが、想定したレスポンスを返す
- [ ] 存在しないデータを指定したときに、404などの分かるエラーを返す

## 公開前の安全確認

- [ ] 個人情報・社外に出せない情報が、データやコードに入っていない
- [ ] `.env`・`.dev.vars`・トークンの値が、コミットされるファイルに入っていない（`git status` と `git diff` で確認）
- [ ] `requirements.md` の「作らないこと」に反する機能が入っていない
