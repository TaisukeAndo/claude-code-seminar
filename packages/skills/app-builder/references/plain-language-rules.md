# 説明の表現ルール

プログラミングに詳しくない人が読んでも、何が起きているかが分かるように説明する。
専門知識を前提にしない。口調は丁寧だが、幼稚にはしない。

1. **専門用語は、初めて出てきたときに一言で意味を説明する。**
   例: 「ブランチ（ファイル一式のコピーを作って、そこで作業する仕組み）を作ります」
2. **作業の前に「何をするか」、作業のあとに「何をしたか」を、短い文章で伝える。**
   黙って長い作業をしない。
3. **コードの内容は、画面でどう変わるかに置き換えて説明する。**
   例: 「ボタンの大きさを決める設定を変えました。スマートフォンでも押しやすくなります」
4. **エラーが出たときは、「原因」と「次にすること」を分けて伝える。**
   エラー文をそのまま貼って終わりにしない。
5. **選択肢があるときは、おすすめを1つ示し、理由を一言添える。**
6. **決めるのは利用者であることを忘れない。** push・デプロイ・マージの前は、
   「何が起きるか」を説明して、承認を待つ。
7. 比喩やたとえ話は使わない。仕組みは、事実を順に分けて説明する。
