# 利用者が自分で操作する手順（画面レベル）

利用者が自分で操作する場面の手順書。AIは、**【あなたにお願いします】と明示して作業を止め、
この手順を1ステップずつ出す。** 書き方は [plain-language-rules.md](plain-language-rules.md) の3章に従う。

**画面の表記は変わることがある。** 手順と違う画面が出たときは、推測で案内せず、
Cloudflareは `docs` ツールで公式ドキュメントを確認する。それでも合わなければ、
利用者に、いま見えているボタンの名前（またはスクリーンショット）を聞く。

この手順書の画面名・ボタン名のうち、公式ドキュメントで確認できたのは次の部分:
Cloudflareの「Create Token」「Custom」「Edit Cloudflare Workers」、アカウントIDの場所
（Workers & Pages → Account Details）。GitHubの画面は、一般に使われている表記。

---

## A. Cloudflare MCPを認証する（初めて接続するとき）

全部で3ステップ。所要は数分。

1. 【AIが行います】接続を開始します。
2. 【あなたにお願いします】ブラウザが自動で開きます。Cloudflareのログイン画面が出たら、
   ログインしてください。
   - 開かないときは、AIが表示するURLを、ブラウザのアドレス欄に貼って開きます
3. 【あなたにお願いします】「AIに許可する権限」を選ぶ画面が出ます。
   このセミナーのアプリでは、**WorkersとD1に関する権限だけ**を許可してください。
   - 関係のない権限（DNS、メールなど）は、許可しません
   - 許可を押すと、ブラウザに「接続できました」といった表示が出ます。ブラウザを閉じて、
     この画面に戻ってください

うまくいったか: 【AIが行います】アカウントの一覧を読み取って、あなたのアカウント名が出るか確かめます。

## B. CloudflareでAPIトークンを作る

GitHub Actionsが、あなたのCloudflareに公開するための許可証を作ります。
**トークンの文字列は、作ったときに一度しか表示されません。会話には貼らないでください。**
全部で7ステップ。所要は5分ほど。

1. 【あなたにお願いします】ブラウザでCloudflareのダッシュボードを開き、ログインします。
2. 【あなたにお願いします】アカウントの管理画面から、「API Tokens」（APIトークン）を開きます。
   - 見つからないときは、画面上部の検索で「API tokens」と入力します
   - 「Account API tokens」（アカウントのAPIトークン）の画面を使います
3. 【あなたにお願いします】「Create Token」（トークンを作成）ボタンを押します。
4. 【あなたにお願いします】「Permission policies」（権限のポリシー）のところで、
   「Custom」のプルダウンを開き、**「Edit Cloudflare Workers」**を選びます。
5. 【あなたにお願いします】**D1の権限を足します。** 権限を追加するボタンを押し、
   「D1」の「Edit」（編集）を選びます。
   - このアプリは、公開のときにD1の表を作るため、D1の編集権限が必要です
   - 「D1」が見つからないときは、AIに伝えてください。AIが公式ドキュメントで確認します
6. 【あなたにお願いします】「トークン名」を、分かる名前（例: `my-app-deploy`）にします。
   対象は、**公開するアカウント1つだけ**に絞ります。
7. 【あなたにお願いします】「Continue to summary」（概要へ進む）→「Create Token」を押します。
   表示されたトークンの文字列は、**このあとのC.で使うので、閉じずに、そのままにしておきます。**
   - 間違えて閉じたときは、トークンを作り直します（古いトークンは、画面から削除できます）

## C. GitHubに、トークンを登録する（ブラウザで行う方法）

トークンを、GitHubの「Secrets」（秘密の文字列をしまっておく場所）に登録します。
**AIとの会話には、トークンを貼らないでください。** 全部で6ステップ。

1. 【あなたにお願いします】ブラウザで、アプリのGitHubのリポジトリのページを開きます。
   （URLは、AIが伝えます）
2. 【あなたにお願いします】上のタブの「Settings」（設定）を押します。
3. 【あなたにお願いします】左のメニューの「Secrets and variables」を押し、
   開いた中の「Actions」を押します。
4. 【あなたにお願いします】「New repository secret」（新しいリポジトリシークレット）ボタンを押します。
5. 【あなたにお願いします】次の2つを入力します。
   - 「Name」（名前）に、次の文字を**そのまま**入力します（大文字・小文字も同じにします）

     ```text
     CLOUDFLARE_API_TOKEN
     ```

   - 「Secret」（秘密の値）に、B.で表示されたトークンの文字列を貼り付けます
6. 【あなたにお願いします】「Add secret」（シークレットを追加）ボタンを押します。
   - 登録したあとは、値を画面で見ることはできません。これは正常です

うまくいったか: 【AIが行います】`gh secret list` で、`CLOUDFLARE_API_TOKEN` の**名前だけ**が
並ぶことを確かめます（値は表示されません）。

アカウントID（`CLOUDFLARE_ACCOUNT_ID`）は秘密の値ではないので、AIが登録します。
AIが登録できないときは、上のステップ4〜6を、Nameを `CLOUDFLARE_ACCOUNT_ID`、
Secretをアカウントのidにして繰り返します。アカウントIDは、Cloudflareの
「Workers & Pages」を開き、「Account Details」の「Account ID」の横のコピーボタンで取れます。

### C'. ターミナルで登録する方法（慣れている人向け）

ブラウザの操作の代わりに、ターミナルで登録することもできます。
ターミナル（Macは「ターミナル」アプリ、Windowsは「PowerShell」）を開き、アプリのフォルダで、次を実行します。

```bash
gh secret set CLOUDFLARE_API_TOKEN
```

「Paste your secret」（秘密の値を貼ってください）と出たら、トークンを貼り付けて、Enterを押します。
貼り付けた文字は画面に表示されませんが、正常です。

## D. 公開の結果を、ブラウザで確認する

1. 【あなたにお願いします】GitHubのリポジトリのページで、上のタブの「Actions」を押します。
2. 一番上の実行（名前は「Deploy」）を見ます。
   - 緑のチェックマーク: 成功です。公開されています
   - 黄色の丸（回っている）: 実行中です。数分待ちます
   - 赤い×: 失敗です。その実行を押して、赤く表示された手順の名前を、AIに伝えてください。
     AIが原因と対処を説明します
3. 【あなたにお願いします】AIが伝えた公開URLを、パソコンのブラウザで開きます。
4. 【あなたにお願いします】**スマートフォンでも開きます。** URLを、自分宛てのメールやメッセージで送り、
   スマートフォンで開きます。同じ画面が出て、同じように動けば完了です。
