# requirements.md のテンプレート

工程1で、利用者との対話の結果をこの形に書き出す。空欄は残さず、決まっていない項目は
「未定（理由）」と書く。

```markdown
# （アプリ名）要件

## 1. 目的
- 解決したいこと:
- 今のやり方（困っていること）:

## 2. 使う人
- 誰が使うか: （自分だけ／社内／一般公開のどれか）
- 使う端末: （パソコン／スマートフォン／両方）

## 3. 扱うデータ
公開しても問題がない情報だけであることを確認した: はい／いいえ

| 表の名前 | 項目（列） | 例 |
|---|---|---|
| （例）items | id, title, created_at | 1, 買い物メモ, 2026-10-18 |

## 4. 画面でできること
- 今回作る機能（1回で作り切れる大きさにする）:
- 次回以降に回す機能（運用の段階で、PRを使って追加する）:

## 5. 作らないこと
- ログイン認証、個人情報の管理、暗号化は今回は作らない
- （そのほか）

## 6. 確認の観点
今回作る機能が動いたと言える条件を、操作の形で書く（機能ごとに1つ以上）。
- （例）題名を入力して「追加」を押すと、一覧の先頭に表示される
```

## 質問のコツ

- 1回の質問は1つだけにする。「誰が」「何を」「どう」をまとめて聞かない
- 利用者の言葉で返す。「テーブル」ではなく「表」と言い、必要なら一言で説明する
- 決められない項目は、例を2〜3個出して選んでもらう
- 要件が大きくなりそうなら、今回作る範囲を絞り、残りは「次回以降」に回す提案をする
