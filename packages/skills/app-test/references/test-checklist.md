# テスト確認項目

アプリに合う項目を選び、今回の変更に関わる項目を重点的に確認する。
結果は「項目／結果（OK・NG）／気づいたこと」の一覧で報告する。

## 起動

- [ ] データの表を作る手順（ある場合）がエラーなく終わる
- [ ] 起動コマンドで起動し、localhostのアドレスが表示される
- [ ] そのアドレスをブラウザで開くと、画面が表示される

## 画面と操作

- [ ] 今回変更した機能が、依頼したとおりに動く
- [ ] 変更していない主な機能も、これまでどおり動く
- [ ] 入力が空のまま送ったときに、分かりやすい表示になる（エラーで止まらない）
- [ ] ページを再読み込みしても、登録したデータが残っている（保存するアプリの場合）
- [ ] 文字が小さすぎず、ボタンが押しやすい大きさになっている
- [ ] ブラウザの幅を狭くしても（スマートフォンの幅）、表示が崩れない

## API（`curl` でも確認する。APIがあるアプリの場合）

- [ ] 死活確認のAPI（`/api/health` など、あれば）が成功（200）を返す
- [ ] データの取得・登録・更新・削除のAPIが、想定したレスポンスを返す
- [ ] 存在しないデータを指定したときに、404などの分かるエラーを返す

## 変更の安全確認

- [ ] 個人情報・社外に出せない情報が、データやコードに入っていない
- [ ] `.env`・`.dev.vars`・トークンの値が、コミットされるファイルに入っていない（`git status` と `git diff` で確認）
- [ ] 依頼にない機能や、関係のないファイルの変更が混ざっていない（`git diff main...HEAD` で確認）
