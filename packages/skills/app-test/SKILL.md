# app-test スキル（テストSkill）

アプリを自分のパソコン（localhost）で動かして、想定どおりに動くか確認する。
localhostは自分のパソコンからしか開けないので、公開前に安心して試せる。

## 守ること

1. **最初に `.claude/rules/expression-rules.md` を読み、その表現のルールに従う。**
   ファイルがなければ、`app-implement` スキルの `assets/rules/expression-rules.md` を同じ場所にコピーしてよい
2. **確認するだけで、本番のデータ・本番の環境には触れない。** localhostのデータだけを使う
3. **テストのために、アプリのコードを書き換えない。** 直すのは、利用者が依頼したとき、または呼び出し元（実装Skill）が直すときだけ
4. **個人情報・トークンを、結果の報告に書かない**

## 手順

### 1. 起動方法を調べる

`README.md`、`package.json` の `scripts` を読み、起動方法を調べる
（調べ方は `app-implement` スキルの `references/stack-detection.md` と同じ）。
一般的な例: 依存の導入 `npm install` → データの表を作る `npm run db:local` → 起動 `npm run dev`。
アプリごとに違うので、**そのアプリのコマンドを使う。** 分からなければ利用者に聞く。

### 2. 起動して、アドレスを案内する

起動し、ブラウザで開くアドレス（例: `http://localhost:8787`）を利用者に伝える。
起動に失敗したら、エラーを「何が起きたか／原因／次にすること」に分けて伝え、直せるものは直す。

### 3. 確認項目を決める

[references/test-checklist.md](references/test-checklist.md) から、このアプリと今回の変更に合う項目を選ぶ。
`requirements.md` があれば、その「今回作る機能」を、確認項目の先頭に足す。
呼び出し元から「変更した機能」が伝えられていれば、その機能と周りの機能を重点的に確認する。

アプリに自動テストのコマンド（`npm test` など）があれば、先に実行する。

### 4. 実際に操作して確認する

- 画面の操作は、書かれた手順どおりに、実際に操作して確認する（ブラウザを操作できない場合は、利用者に操作をお願いし、結果を聞く）
- APIは `curl` で確認する
- 1項目ごとに、結果（OK／NG）と気づいたことを記録する
- 確認の途中で、何件終わったかを知らせる（例: 8件中5件）

### 5. 結果を報告する

次の形で、一覧にして報告する。

| 項目 | 結果 | 気づいたこと |
|---|---|---|
| 一覧が表示される | OK | |
| 空のまま送信する | NG | エラーで止まる |

- NGがあれば、原因の候補を説明する（確証がなければ「候補」と断る）
- 最後に、**全項目OKか、NGが残っているか**を一言で示す
- localhostを起動したままにしたときは、止め方を伝える
