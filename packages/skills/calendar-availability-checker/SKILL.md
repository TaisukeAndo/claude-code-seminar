# calendar-availability-checker スキル

## このスキルがすること

1. Googleカレンダー（複数アカウント・複数カレンダーを横断できる）またはOutlookカレンダーから、
   指定期間の予定を取得する
2. 平日の指定時間帯（デフォルト9:00-18:00、12:00-13:00の昼休みを除く）から予定を
   差し引き、まとまった空き時間（デフォルト60分以上）を計算する
   - 対面の予定の直後（次に何も予定が無くても）、対面の予定の直前（前が
     オンラインの予定や何も無い状態でも）には、移動時間として30分のバッファを
     確保する
   - これから調整しようとしている新しい予定が対面の場合も、その日の直前の予定
     との間に同様に30分のバッファを確保する（オンラインの場合は不要）
   - 同じ隙間（前後の予定の間）にバッファが必要な理由が複数重なっても、
     合計せず常に最大30分までしか空き時間を削らない（前後合わせて60分には
     ならない）
3. 空き時間を日付ごとに箇条書きでユーザーに報告する

予定の内容（タイトルなど）は空き/予定ありの判定にのみ使い、報告には含めない。

## ディレクトリ構成

```
.claude/skills/calendar-availability-checker/
├── config/
│   └── google_calendars.txt    ← 空き判定に含めるGoogleカレンダーIDの一覧（編集自由）
└── scripts/
    └── compute_free_slots.py   ← 予定一覧から空き時間を計算し、整形済みの箇条書きテキストも出力する
```

## なぜ複数カレンダーに対応する必要があるのか

会社用と個人用でGoogleアカウントを分けている、部署共有のカレンダーも一緒に
確認したい、といったケースは珍しくない。1つのカレンダーだけを見て「空いている」と
判断すると、実際には別のカレンダーに予定が入っていて二重予約になってしまう。
このスキルは `config/google_calendars.txt` に登録したカレンダーIDをすべて横断して
確認し、重複する時間帯は自動でマージしたうえで空き時間を計算する。

## なぜ計算をスクリプトに任せるか

複数日にまたがる予定のマージ、勤務時間との重なり判定、閾値未満の除外といった
時刻計算は、LLMが暗算すると区間の重複処理や日またぎでミスが出やすい。決定的な
Pythonスクリプトに計算部分を任せ、Claudeは「予定の取得」と「結果の報告」に専念する。

## Step 1: 対象カレンダーを決める

- ユーザーが「Googleで」「Outlookで」のように明示していればそれに従う
- 明示がなく、接続されているカレンダー連携が実質1つだけなら、確認せずそれを使う
- 明示がなく、両方使える状態なら、ユーザーにどちらか確認する
- Outlookが指定されたが接続が見当たらない場合は、Step 3の「Outlookカレンダーの場合」
  の手順に従う
- Googleを使う場合、どのGoogleカレンダー（アカウント）を対象にするかは
  `config/google_calendars.txt` に登録する。初回利用時は空欄（コメントのみ）なので、
  ユーザーに「確認したいGoogleカレンダーのメールアドレスを教えてください（複数可）」と
  尋ね、教えてもらったIDを1行ずつファイルに書き込む。デフォルトではこのファイルに
  書かれたカレンダーすべてを毎回自動でまとめてチェックする（2回目以降は確認不要）
  - ファイルが空（コメントのみ）の場合は primary のみを対象とする
  - ユーザーが「今回だけ○○のカレンダーも見て」と言った場合は、その回だけ一時的に
    対象カレンダーIDを追加する（ファイルは変更しない）
  - ユーザーが「いつも○○も見て」「これから毎回含めて」「○○はもう見なくていい」の
    ように恒久的な変更を頼んだ場合は、`config/google_calendars.txt` を直接編集する
    （祝日カレンダーや学年暦のような「情報カレンダー」は個人の予定ではないため、
    追加を頼まれても一言注意を促してよい）

## Step 2: 条件を確認する

| 項目 | デフォルト | ユーザー指示の例 |
|---|---|---|
| 対象期間 | 今日から2週間（14日間） | 「来週だけ」「今月末まで」「今日から1ヶ月」 |
| 時間帯 | 9:00-18:00（12:00-13:00の昼休みを除く） | 「午前中だけ」「10時から17時で」「昼休みも含めて」 |
| 曜日 | 平日のみ（月〜金） | 「土日も含めて」 |
| 最低空き時間 | 60分以上 | 「30分でもいいから知りたい」「2時間以上でまとめて」 |
| 新規予定の形式（対面/オンライン） | 不明な場合はオンライン扱い（移動バッファなし） | 「対面で会いたいので」「〇〇さんのオフィスに訪問したい」「オンラインでいい」 |

ユーザーから特に指定がなければ、聞き返さずデフォルト値のまま実行してよい。
このスキルは日程調整のたびに気軽に使われる想定なので、毎回条件確認を挟むと
かえって手間になる。逆に指定があれば、その条件を優先する。

新規予定の形式は、ユーザーの依頼文から「対面」「訪問」「会う」「現地」などの
表現があれば対面、「オンライン」「Web」「Zoom/Meet」などの表現があればオンラインと
判断する。判断材料が無ければ、移動を強制しないようオンライン扱い（バッファ無し）を
デフォルトとする。ただし依頼内容が「〇〇さんとランチ」「〇〇さんの会社に伺う」の
ように対面が前提の用件であることが明白な場合は、聞き返さず対面として扱ってよい。

## Step 3: 予定を取得する

### Googleカレンダーの場合

1. `config/google_calendars.txt` を読み、対象カレンダーID一覧を得る
   （`#`始まりの行と空行は無視する。ファイルが空/未設定ならStep 1の手順でユーザーに確認する）
2. `list_calendars` で各カレンダーの`timeZone`を確認する
3. 対象カレンダーIDごとに `list_events` で対象期間の予定を取得する
   - `calendarId`: 対象のカレンダーID
   - `startTime`/`endTime`: 対象期間の開始日 00:00 〜 終了日 23:59
     （手順2で確認したタイムゾーンのオフセット付きで指定する）
   - `eventType` は指定しない（省略時のデフォルトで`DEFAULT`/`OUT_OF_OFFICE`/
     `FOCUS_TIME`/`FROM_GMAIL`が返る。これらはすべて「予定あり」として扱ってよい）
4. 終日予定（`allDay: true`、またはレスポンスの`start`/`end`が`date`のみで`dateTime`が
   無いもの）は、**原則として空き判定に含めない**（busy_intervalsに入れない）。
   誕生日リマインダーや「日本の祝日」カレンダーの登録日など、実際には時間を
   占有しない終日イベントが多いため、終日＝busy扱いにすると空きが不当に減ってしまう。
   ただし件名から「休暇」「有給」「出張」「終日不在」など明らかにその日1日
   不在であることを示す終日予定は、その日をbusyとして扱ってよい
5. 予定が多くページングされる場合は`nextPageToken`を辿ってすべて取得する
6. 各予定が対面かオンラインかを判定し、対面と判断した予定には
   Step 4で`is_in_person: true`を付ける（判定方法は下記）
7. 全カレンダー分の予定をひとつの`busy_intervals`にまとめる。同一カレンダー間・
   カレンダーをまたいだ重複時間帯は、Step 4のスクリプトが自動でマージするので
   気にしなくてよい

#### 対面/オンラインの判定方法

移動時間バッファを正しくかけるため、各予定について次の優先順位で判定する。

1. `conferenceUrl`（Google Meetのリンク）がある、または`location`に
   Zoom/Meet/Teams/Webex/オンライン等の文字列が含まれる → **オンライン**
2. `location`に住所・駅名・建物名・店名など具体的な物理的場所が入っている、
   または件名が「移動」「訪問」「出張」「ランチ」「飲み」など対面を前提とする
   内容 → **対面**
3. どちらの手がかりも無い（`location`も`conferenceUrl`も無い社内の作業ブロック等）
   → 対面かどうか判断できないため、バッファを付けない（`is_in_person`を付けない）

判定に迷うケースでも、ここでユーザーに逐一確認はしない（このスキルは気軽な利用を
想定しているため）。誤判定の影響は「対面予定の後ろに30分の余白ができる/できない」
程度に限られ、安全側（バッファを付けない）に倒すほうが実害が小さい。

### Outlookカレンダーの場合

現時点でこの環境にOutlook用のMCPツールが接続されているとは限らない。以下の手順で
その場で確認する。

1. `ToolSearch` で `"outlook calendar"` や `"microsoft calendar events"` 等の
   キーワードから該当ツールを探す
2. 見つかった場合、そのツールのパラメータ・レスポンスのスキーマを確認し、
   Google側の`list_calendars`/`list_events`に相当する操作
   （期間を指定して予定一覧を取得する）を行う。フィールド名はツールにより異なるが、
   一般的には開始/終了日時、終日フラグ、空き/予定ありステータス
   （`showAs`等）に相当する情報が含まれる
3. 見つからない場合は、ユーザーにOutlook/Microsoft連携の接続を促す。接続してもらって
   から改めてStep 3を実行する。接続なしで処理を進めない
4. 終日予定や、明示的に「空き」扱い（transparent/free）とマークされた予定は
   空きなしの判定から除外する

## Step 4: 空き時間を計算する

取得した予定を、開始・終了のISO 8601（タイムゾーンオフセット付き）のペアの
リストにまとめ、以下のフォーマットでJSONをスクラッチ領域に保存する。

```json
{
  "start_date": "YYYY-MM-DD",
  "end_date": "YYYY-MM-DD",
  "work_start_hour": 9,
  "work_end_hour": 18,
  "lunch_break_start_hour": 12,
  "lunch_break_end_hour": 13,
  "weekdays_only": true,
  "min_slot_minutes": 60,
  "timezone": "Asia/Tokyo",
  "new_meeting_is_in_person": false,
  "busy_intervals": [
    {"start": "2026-07-14T10:00:00+09:00", "end": "2026-07-14T11:00:00+09:00", "is_in_person": true},
    {"start": "2026-07-14T14:00:00+09:00", "end": "2026-07-14T15:00:00+09:00"}
  ]
}
```

`lunch_break_start_hour`/`lunch_break_end_hour`はデフォルトで12-13を自動的に
busy扱いにする（ユーザーが「昼休みも空きに含めて」等と指示した場合のみ、両方に
`null`を指定して無効化する）。

`busy_intervals`の各要素は、対面と判定した予定にのみ`is_in_person: true`を付ける
（オンライン・判定不能な予定は省略してよい。省略時はfalse扱い）。
`new_meeting_is_in_person`は、Step 2で判断した「これから調整する新しい予定」の
形式を渡す（対面ならtrue、オンライン・不明ならfalse）。

これらのフィールドにより、スクリプトは以下の移動時間バッファを自動で考慮する
（デフォルトどちらも30分。ユーザーが「移動時間は15分でいい」等と指示した場合のみ
`in_person_travel_buffer_minutes`/`travel_buffer_before_minutes`を明示的に変更する）。

- 対面（`is_in_person: true`）の予定の**直後**の隙間には、直後に何も予定が
  無くても`in_person_travel_buffer_minutes`（既定30分）を確保する
- 対面の予定の**直前**の隙間にも、直前がオンラインの予定や空白でも同じく
  `in_person_travel_buffer_minutes`を確保する（「対面の予定の前にオンラインMTGが
  詰まっていて移動時間が無い」を防ぐため）
- `new_meeting_is_in_person`がtrueの場合、その日の直前に何らかの予定がある
  空き枠には`travel_buffer_before_minutes`（既定30分）を確保する
  （その日の一番最初の空き枠のように、直前に予定が無い場合はバッファを付けない）

同じ隙間で複数の理由（直前の予定が対面／直後に控える予定が対面／新規予定が対面）が
重なっても、スクリプトは合計せず常に片側だけ・最大30分までしかその隙間を削らない
（前後合わせて60分にはならない）。

実行する:

```bash
python3 .claude/skills/calendar-availability-checker/scripts/compute_free_slots.py /path/to/input.json
```

出力される`bullet_list_text`が、そのままユーザーに提示できる箇条書きになっている。

---

## Step 5: 結果を報告する

- 冒頭で「対象カレンダー（Google/Outlook、複数ある場合はどのアカウント）」
  「対象期間」「時間帯の条件」を一言添える
- `new_meeting_is_in_person`をtrueにして計算した場合は、「対面を想定し前後30分の
  移動時間を確保して計算しています」等、その旨も一言添える
- スクリプトが返した箇条書き（`bullet_list_text`）をそのまま提示する
- 条件を満たす空きが1件もなかった場合は、その旨と使った条件を伝えたうえで、
  期間を広げる・最低時間を短くするなどの提案をする

---

## 注意事項

- 予定のタイトルや参加者など内容そのものは、空き/予定ありの判定にのみ使い、
  ユーザーへの報告には含めない（プライバシー配慮。「予定あり」の事実のみ扱う）
- タイムゾーンは対象カレンダーの設定に従う。判断がつかない場合は`Asia/Tokyo`を使う
- `config/google_calendars.txt` には自分のメールアドレスが入るため、GitHubで
  管理する場合は公開リポジトリにpushしないよう注意する
